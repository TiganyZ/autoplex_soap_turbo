# Seed data for the water dipole workflow

`training.yaml` reads `dataset.initial` from this directory.

## The checked-in file

`example_synthetic.xyz` — 60 water monomers and dimers whose dipoles come from a
fixed point-charge model, generated by `make_example.py`.

It is here so that a fresh installation can be exercised end to end before any
DFT has run:

```bash
python workflows/water_dipole/run.py --dry-run
```

**It is not reference data.** A model fitted to point charges reproduces point
charges. Do not draw conclusions from a run against it.

## Using your own data

The workflow expects an extxyz file whose `info` carries the dipole under the
key named by `dataset.dipole_key` (`mu` by default), and optionally the
polarizability under `dataset.polarizability_key` (`alpha`).

`autoplex-st-prepare-water` does the conversion — units, the cell that
`soap_turbo` needs, and dropping the fields that are not fitted:

```bash
autoplex-st-prepare-water /path/to/water_dipole_tnep.xyz \
    -o data/initial.xyz \
    --dipole-unit atomic \
    --polarizability-unit bohr^3
```

Then point `dataset.initial` at `data/initial.xyz`.

The `--dipole-unit` is the one thing worth checking twice: an atomic-unit dipole
read as e·Å fits perfectly well and is wrong by a factor of 1.9. The choices are
`e*angstrom`, `atomic` (e·bohr), `debye` and `hartree*bohr`; the prepared file
records which conversion was applied in an `autoplex_st_units` entry, so a
dataset can say what convention it is in.

Frames without a dipole are dropped, with a count reported. If everything is
dropped, `--dipole-key` does not match what is in the file's extxyz header.
