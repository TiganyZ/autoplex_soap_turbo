# Long IR runs: every timestep, 50 ps, from the equilibrated structures

> Regenerated by [`../regenerate.sh`](../regenerate.sh) into `out/long_run/`; paths below are relative to that directory.

Four MD runs on Roihu with the dipole recorded at **every MD step**, replacing
the earlier 2 fs-sampled 2 ps analysis window.

## What changed against the short runs

| | short runs | these |
|---|---|---|
| sampling | every 8th step (2 fs) | **every step (0.25 fs)** |
| run length | 10 ps (1000 frames used) | **50 ps** |
| samples in the estimate | 1 000 | **200 001** |
| longest lag | 400 fs | 3.1 ps (`ir_lag_factor = 16`) |
| resolution | 83.4 cm^-1 | **10.7 cm^-1** |
| variance per point | (max lag)/N = 1/2 | **1/16 — 8x lower** |
| Nyquist | 8 339 cm^-1 | 66 713 cm^-1 |
| smoothing | 10 bins baked in by turboGAP | **none — applied in post, adjustable** |

## The arms

`{classical Bussi, quantum GLE} x {old dipole model, r119}`. The dynamics do not
depend on the dipole model and the seed is fixed, so within a thermostat both
models see the **same trajectory** — which makes each pair a controlled test of
the dipole model alone.

Starting configurations are the equilibrated structures: `equilibrated.xyz` for
the classical arm, and for the quantum arm the **last frame of the existing GLE
production run**, which is equilibrated under exactly this thermostat rather
than merely thermalised.

van der Waals is on throughout (`vdw_type = ts`, `vdw_rcut = 25.0`).

## Two turboGAP defaults that would have spoiled this

**`ir_nu_max` defaults to 4000 cm^-1** — inside the OH stretch. Left alone it
truncates the band and distorts its top. It is set to 5000 in every deck. This
is the same trap that produced wrong peak positions in the earlier analysis (see
`docs/water-dipole-training.md` Part 16).

**`ir_resolution` defaults to 20 cm^-1, and naming it CAPS the ensemble.**
Leaving it out makes turboGAP use the whole run (`turbogap.f90:1396`,
`ir_resolution_set`). It is deliberately absent from the decks.

## ir_lag_factor, and the trap in "just run it longer"

**A longer run on its own buys no signal-to-noise.** The variance of a
Blackman-Tukey spectral estimate goes as (max lag)/(n samples). turboGAP's
default `ir_lag_factor = 2` sets max lag = N/2, so that ratio is pinned at 1/2
*whatever N is*. Going 10 ps -> 50 ps at the default multiplies the number of
frequency bins and leaves each one exactly as noisy as before. It buys
resolution, and only resolution.

This was caught by looking at a partial run: at ~11 000 steps the raw curve was
already very spiky, and nothing about reaching 200 000 steps would have fixed
it.

To turn length into signal, hold the lag fixed and let the extra length average
more pairs — which is what a larger `ir_lag_factor` does:

| ir_lag_factor | longest lag | resolution | variance vs default |
|---|---|---|---|
| 2 (default) | 25 ps | 1.33 cm^-1 | 1x |
| 8 | 6.2 ps | 5.3 cm^-1 | 4x lower |
| **16 (used here)** | **3.1 ps** | **10.7 cm^-1** | **8x lower** |

16 is chosen because 3.1 ps is several dipole correlation times in liquid water
(1-2 ps), beyond which the ACF carries no signal to transform, while 10.7 cm^-1
still resolves every feature comfortably — the narrowest real one is the HOH
bend at 80-100 cm^-1 wide, and the OH stretch is ~340.

The spectrum on disk is still unsmoothed, so any further smoothing remains a
post-processing choice; ~25 cm^-1 is a sensible reading width.

    python scripts/long_run_figures.py                       # raw + 25 cm^-1
    python scripts/long_run_figures.py --smooth 40           # gaussian FWHM, cm^-1
    python scripts/long_run_figures.py --smooth 0            # no smoothing
    python scripts/long_run_figures.py --ladder 0 10 25 50 100
    python scripts/long_run_figures.py --smooth 30 --kernel boxcar
    python scripts/long_run_figures.py --smooth 9 --units bins
    python scripts/long_run_figures.py --xlim 2000 4500

Every curve is scaled to unit area over 400-4000 cm^-1, so arms are comparable
without fitting anything per curve. The run's own resolution is drawn on each
panel as a green bar, so a chosen smoothing width can be read against the width
below which nothing is meaningful.

Kernel edges are handled by reflection rather than zero padding: a spectrum does
not fall to zero at the edge of the computed window, and zero padding drags the
first and last points towards it, which looks like a real falling edge.

### The lag-factor claim, measured

Verified on ONE fixed dipole series (1000 frames, quantum/r119) with the lag
factor as the only variable, since that is the only way to isolate it:

| ir_lag_factor | bin cm^-1 | per-point noise |
|---|---|---|
| 2 | 16.7 | 0.0867 |
| 4 | 33.4 | 0.0566 |
| 8 | 67.0 | 0.0381 |
| **16** | 135.6 | **0.0247** |
| 32 | 273.4 | 0.0076 |

Each doubling cuts the noise by ~1.5x against the sqrt(2) = 1.41x expected, and
2 -> 16 gives 3.5x (theory 2.83x). The last row rests on 10 points, so read it
loosely.

**Two ways of measuring this that do NOT work**, both tried first:

- *Second differences as a roughness measure.* They scale as (bin width)^2, so
  a spectrum on 8x coarser bins scores ~64x rougher no matter how clean it is.
  It reported the change as a 10x REGRESSION.
- *Comparing two partial runs.* The lag_factor 2 and 16 partials had different
  run lengths AND different bin widths, and a residual-from-smoothed metric
  depends on the kernel width in BINS, which differed 8x. It reported no change.

Only a fixed series with one variable settles it.

### What the deck actually produced

The header turboGAP writes into every `ir_spectrum.dat` confirms the design,
and is worth reading rather than assuming:

```
  MD timestep                  =         0.2500 fs
  sampling interval dt         =         0.2500 fs
  longest lag transformed      =          12500
  longest lag sized for        =          12500
  nu power p                   =         2.0000
  lag window                   =           hann
  ACF estimator                =  biased, 1/N
  TRUSTWORTHY RANGE:       10.67  to     5000.00  cm^-1
  Nyquist limit                =     66712.82 cm^-1
```

The lag is sized ONCE, from the planned run length: 200000/16 = 12500 steps =
3.125 ps, giving 33356.4/3125 = 10.67 cm^-1. It does not grow with the run. That
is the whole point of naming `ir_lag_factor` rather than letting the default
lag = N/2 track the length: the resolution is pinned at 10.67 cm^-1 from step
one, and every further step goes into lowering the variance, which falls as
lag/N. Under the default the ratio would have stayed at 1/2 forever and a longer
run would have bought resolution and no noise reduction at all.

Against the short 1000-frame predictions the grid is 469 points at 10.68 cm^-1
rather than 120 at 41.5 cm^-1 -- 3.9x finer, and one grid point per resolvable
element, so nothing is oversampled.

### Reading the smoothing ladder

The grid spacing (10.68 cm^-1) equals the resolution, so a smoothing FWHM below
about 11 cm^-1 is narrower than one bin and is a no-op: the `--ladder 10` rung
lies on top of the raw curve by construction, and is included only to show
where the floor is. 25 cm^-1 (2.3 bins) is the default because it is the
narrowest width that visibly suppresses point-to-point scatter without touching
the band envelopes; by 100 cm^-1 the curve has stopped changing, which says the
envelope is fully resolved and the rest is noise.

### `write_xyz` silently controls the IR cost, and it is O(N^2)

The run does NOT reach 200000 steps, and the reason is a deck setting that
looks like it only concerns trajectory output.

Three timing points for `classical_old`, measured against a job start of
17:20:00:

| elapsed s | steps | implied s/step |
|---|---|---|
| 4256 | 26240 | 0.162 |
| 11275 | 52428 | 0.215 |
| 33035 | 101268 | 0.326 |

The cost per step doubles over the run. Fitting the first and last to
`t = a N + b N^2` gives

```
t = 0.1048 N + 2.186e-6 N^2
```

which reproduces the held-out middle point to 2%. Two things fall out of it:

- **The linear term, 0.105 s/step, is the `test`-partition calibration
  (0.110).** That calibration was not wrong. It was short, so `N` never grew
  enough for the quadratic term to show, which is precisely the condition under
  which a calibration cannot see this.
- **Reaching 200000 steps would take 30.1 h, not 12.** Inside the 12 h
  walltime the run reaches ~118600 steps = 29.7 ps, 59% of target.

The mechanism, confirmed in `turbogap.f90` rather than inferred:

```fortran
call get_write_condition(..., params%write_xyz, write_condition)   ! :2601
if (rank == 0 .and. params%write_ir .and. mad_ir_have_spectrum &
    .and. write_condition) then
   call mad_ir_spectrum(mad_ir_state)                              ! :2625
```

The IR spectrum is recomputed **on `write_xyz` steps**. The deck sets
`write_xyz = 4` -- chosen to get a 1 fs trajectory for cross-checks -- so the
whole accumulated dipole history is re-transformed every 4 MD steps, 50000
times over a 200000-step run. And the header says `ACF estimator = biased,
1/N`, not the exponential mode whose `acf()` is maintained incrementally by
`mad_ir_advance_aux` at fixed cost, so each of those recomputes is over the
FULL history and grows with it. (N/4) recomputes each costing O(N) is the
O(N^2) term.

**For any future long run: raise `write_xyz`.** At `write_xyz = 400` (a 100 fs
trajectory, still ample for cross-checks) the quadratic coefficient falls 100x
and 200000 steps costs `0.1048*2e5 + 2.186e-8*4e10` = 21800 s = 6.1 h. The
trajectory stride and the IR recompute interval are the same knob, and only
one of them was being thought about when it was set.

### What the shortfall actually costs

Nothing in resolution, and little in noise:

| | planned | actual |
|---|---|---|
| steps | 200000 | ~118600 |
| length | 50.0 ps | 29.7 ps |
| resolution | 10.67 cm^-1 | **10.67 cm^-1** (lag fixed at 12500) |
| lag/N | 1/16.0 | 1/9.5 |
| noise | 1.00 | 1.30 |

The resolution is untouched because the lag was sized once from the PLANNED
length and does not track the run. That is the same property that made naming
`ir_lag_factor` worth doing, working in the other direction: a run cut short
keeps its resolution and gives back only variance.

### The paired arms share a trajectory, verified

The two classical arms differ ONLY in the dipole model, and so do the two
quantum arms. This is not an argument from the deck, it is measured:

```
md5sum */atoms.xyz          classical_old == classical_r119
                            quantum_old   == quantum_r119
random_seed = 12345         in all four decks
head -100000 thermo.log     classical_old == classical_r119  (143617cf428a)
                            quantum_old   == quantum_r119    (9e1f00922bbd)
```

Bit-identical thermodynamic traces over 100000 steps. The dipole model does not
enter the forces -- only the energy model does, and `potentials/old` and
`potentials/r119` carry the SAME `energy.gap` with different dipole blocks --
so the dynamics are held exactly fixed and every spectral difference within a
pair is the dipole model.

**This corrects a claim in `run_predictions.sh`**, which says that on a shared
trajectory "band POSITIONS cannot move between them -- only intensities". Too
strong. The frequencies PRESENT are fixed, but the OH stretch is a broad
composite of many local environments, and its peak is an intensity-weighted
quantity. A dipole model that reweights which environments radiate moves the
peak without changing a single frequency in the trajectory. That is what
3580 -> 3388 cm^-1 in the classical pair is.

### The OH peak is not a usable statistic here; the centroid is

A finer grid tempts a finer question, and the argmax does not survive it.
Between the 99000-step and 110000-step snapshots of the SAME runs:

| arm | argmax @99k | argmax @110k | stretch share @99k -> @110k |
|---|---|---|---|
| classical_old | 3580 | 3509 | 0.449 -> 0.448 |
| classical_r119 | 3388 | 3580 | 0.531 -> 0.530 |
| quantum_old | 3994 | 3994 | 0.301 -> 0.301 |
| quantum_r119 | 3771 | 3772 | 0.470 -> 0.471 |

The classical argmax moved up to 192 cm^-1 -- 18 resolution elements -- on 11%
more data, while every integrated quantity held to the third decimal. So an
earlier reading of this table, that round 3 had moved the classical peak to
3388 and onto Downing's 3416, was noise and is withdrawn.

`n_competing` says why: interior local maxima within 90% of the window maximum.

| arm | ncomp | centroid |
|---|---|---|
| classical_old | 2 | 3523 |
| classical_r119 | 3 | 3562 |
| quantum_old | 6 | 3819 |
| quantum_r119 | 2 | 3651 |
| **Downing** | **1** | **3368** |

The measurement has ONE stretch maximum. Every model arm has two to six of
comparable height, so the argmax is a toss-up among them and carries no more
precision than their spread. The intensity-weighted centroid of the same window
integrates instead of picking, and is stable for the same reason the band
shares are.

**On the centroid the long runs CONFIRM the short runs rather than overturning
them.** Round 3 moves the quantum-thermostat centroid 3819 -> 3651, i.e. 168
cm^-1 toward experiment, alongside stretch share 0.301 -> 0.471 (target 0.687)
and mismatch 0.937 -> 0.835. The classical arm is a wash: 39 cm^-1 the wrong
way in position, better in share (0.448 -> 0.530). That is the same split the
1000-frame predictions reported at 41.5 cm^-1, now at 10.67 cm^-1 with the
dynamics held bit-identical within each pair.

### What it says

**Quantum thermostat: round 3 is a clear improvement**, on every stable measure
at once -- centroid 3819 -> 3651 (168 cm^-1 toward experiment), stretch share
0.300 -> 0.471 against a target of 0.687, mismatch 0.936 -> 0.837. The two
curves in that panel come from a bit-identical trajectory, so that is the
dipole model and nothing else.

**Classical MD: no improvement in position.** Centroid 3521 -> 3563, i.e. 42
cm^-1 the WRONG way, with a better stretch share (0.450 -> 0.530) and a
marginally worse mismatch. A wash.

This is the same split the 1000-frame predictions reported at 41.5 cm^-1, now
confirmed at 10.67 cm^-1 with the dynamics controlled. The long runs did not
overturn the short ones; they made the classical arm's flatness unambiguous and
removed the possibility that the quantum arm's gain was a sampling artefact.

**The residual is the energy model, not the dipole model.** Both quantum arms
put the stretch far blue of 3368 -- the GLE over-pumps it against a potential
whose reference is plain PBE with no dispersion -- and no reweighting of
intensity can move a band the dynamics do not produce. r119 closes 168 cm^-1 of
a 451 cm^-1 gap; the remaining 283 is not the dipole model's to close.
